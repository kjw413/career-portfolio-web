## 2. 컨셉

**"공장 데이터를 모으고, 자동화하고, 예측합니다."** — 첫 화면 제목이 곧 장면의 줄거리다.

- 무대: 어두운 관제실. 남한 지도 위 다섯 사업장에서 데이터가 솟아 통합 화면(패널 링)으로 모인다. (기존 장면 유지·확장)
- 스크롤하면 같은 무대에서 카메라가 제목의 세 동사를 차례로 비춘다.
  1. **모으고** — 지도 가까이: 다섯 사업장과 솟아오르는 원천 데이터(주황)
  2. **자동화하고** — 링 아래 검증 게이트: 알갱이가 게이트를 지나며 주황 → 하늘색(표준 데이터)으로 바뀐다
  3. **예측합니다** — 앞 패널: 실측선과 P05~P95 예측 구간
- 각 단계의 글은 프로젝트 사례에 이미 적힌 사실만 쓴다. 수치는 첫 화면 HUD와 `주요 성과`에 있으므로 단계 글에서 되풀이하지 않는다.

## 3. 지키는 결정과 바꾸는 결정

| 기존 결정 (v2) | 이번 | 이유 · 보완 |
|---|---|---|
| 3D는 1개 장면만, 카드·섹션 배경에 흩뿌리지 않음 | **유지** | WebGL 장면은 여전히 하나. 첫 화면 + 단계 설명이 같은 캔버스를 공유한다 |
| 카드 포인터 기울기, 섹션 격자 배경 넣지 않음 | **유지** | 흔한 장식이고 수치를 묻는다. 깊이감은 장면과 레이어(유리 HUD, 그림자)로만 낸다 |
| 포인터 시차 없음 (2026-09-26 제거) | **유지** | — |
| 수치 조건을 항상 보이게, 숫자가 경험 카드로 연결 | **유지** | `Hero.test.tsx`가 계속 지킨다 |
| 첫 화면에 학력·경력·자격 | **유지** | 명판(nameplate) 형태로 첫 화면 안에 둔다 |
| 3D는 첫 화면 밖 독립 띠 | **변경** → 첫 화면 전면 무대 | 요청이 "3D 웹페이지"다. 글·수치는 HTML로 장면 위에 얹고, 글 뒤에 어두운 막을 깔아 가리지 않게 한다. 캔버스는 지금처럼 유휴 시간에 지연 로드 |
| 스크롤에 따른 카메라 이동 없음 | **변경** → 단계 사이에서만 이동 | 이전 거절 이유는 "띠라서 필요가 적고, 읽는 동안 움직이면 방해". 이번에는 전면 고정 무대이고, 단계 글이 화면 가운데 있는 동안 카메라는 멈춰 있다(구간별 고정 + 사이 보간) |

## 4. 화면 구조

```
[머리글]  무대 위에서는 투명, 무대를 지나면 불투명. 스크롤을 따라옴 + 읽기 진행 막대
[무대 ─ 캔버스 고정(sticky)]
   ├ 첫 화면: 제목 · 요약 · 버튼 · 명판(학력/경력/자격/연락처) │ 오른쪽 3D │ 하단 수치 HUD 4칸
   └ 단계 01 모으고 → 02 자동화하고 → 03 예측합니다 (각 단계 글 카드, 카메라 이동)
[주요 성과] [대표 프로젝트 3열 벤토: 1번 2칸 + 4장] [경력·교육] [보유 기술] [전체 프로젝트] [학력·자격·병역] [연락처]
```

- 본문은 최대 1240px 중앙 정렬(A6). 섹션 머리는 번호 + 영문 소제목 + 한글 제목으로 통일.
- 대표 프로젝트: 3열 격자에서 1번 카드가 2칸 → 5장이 빈칸 없이 2줄(A3). 1180px 이하 2열(1번 전폭), 720px 이하 1열.
- `학력·자격·병역` 왼쪽 블록은 원색 파랑 대신 무대와 같은 남색(A4).
- 모바일(<720px): 3D 대신 포스터. 첫 화면은 글 → 포스터 → 명판 → 수치 순, 단계는 고정 없이 카드로 흐른다.

## 5. 3D 장면 변경

| 요소 | 내용 | 비용 |
|---|---|---|
| 카메라 리그 | 첫 화면 + 단계 3개 = 키프레임 4개. 스크롤 위치를 받아 구간별 고정 + 사이 보간, 감쇠로 부드럽게 | 계산만 |
| 알갱이 색 | 원천(주황) → 게이트 통과 후 표준(하늘색). 정점 색으로 Points 한 번에 그림 | draw call 0 추가 |
| 검증 게이트 | 링 바닥 아래 두 겹 고리 + 도는 눈금 | +2~3 |
| 사업장 빛기둥 | 다섯 사업장 위 세로 빛. InstancedMesh 1개 | +1 |
| 바닥 격자·안개 | 지도 밖으로 이어지는 옅은 격자 + 거리 안개로 깊이감 | +1 |

예산: 삼각형 ≤ 20,000(현재 896), 3D 청크 gzip ≤ 250KB(현재 236KB → 여유 14KB). 새 three 모듈을 들이지 않는다.
장면을 바꾸므로 원장 `scene-*` 수치를 다시 재서 고치고, 포스터를 다시 만든다.

## 6. 시각 체계

- 무대(테마 무관 어두움): `#050b18 → #0a1730`, 하늘색 빛 `#4fd8ff`, 원천 데이터 주황 `#ffb347`
- 본문: 기존 토큰 유지(밝은 `#f8fafc` / 어두운 `#0a1020`, 강조 파랑). 그라데이션·유리 질감은 무대 위 HUD에만
- 글꼴: Pretendard(본문·제목), IBM Plex Mono(큰 수치만). 제목을 키우고 자간을 좁혀 위계를 분명히
- 움직임: 무대 밖은 등장 효과만(지원 브라우저, 모션 축소 시 끔)

## 8. 검증 기록

로컬 정적 빌드(`out/`)를 Playwright(Chromium, SwiftShader WebGL)로 열어 캡처했습니다.
글꼴은 배포와 같은 Pretendard를 로컬에 설치해 렌더했습니다.

| 회차 | 발견 | 조치 |
|---|---|---|
| 1 | 첫 화면이 900px을 넘어 명판·수치 아래 줄이 잘림(V1) | 제목·여백을 화면 높이에 맞춰 줄이고, 왼쪽 단을 620px로 넓혀 요약을 3줄로 |
| 1 | 수치 HUD가 지도 남쪽(경산·김해)을 가림(V2) | 첫 화면 카메라를 낮추고 물려 장면을 HUD 위로 |
| 1 | 단계 2: 카메라가 낮아 패널 모서리가 화면을 가르고 게이트가 읽히지 않음(V3) | 위에서 내려다보는 구도 → 3회차에 패널 사이 틈(26°)으로 이동 |
| 1 | 사업장 빛기둥이 굵어 남양주 이름표를 가림(V2) | 반지름·높이·불투명도 축소 |
| 1 | 단계 1에서 첫 화면 끝부분이 투명 머리글 밑으로 겹침(V4) | 무대 위에서 스크롤하면 머리글에 반투명 막 + 흐림 |
| 1 | **버그**: 고정된 3D 층이 무대 끝을 넘어 '주요 성과' 제목을 덮음 | 음수 여백 대신 무대 높이의 트랙 안에 고정(sticky) |
| 1 | 태블릿: 첫 화면이 화면보다 길어 단계 위치와 카메라 단계가 어긋남(V3) | 단계 값을 단계 글의 실제 위치로 계산(`stageValue`, 단위 테스트 추가) |
| 2 | 1440×800에서 62px 넘침(V1) | 높이 860px 이하에서 이름 줄을 감추고 제목 축소(이름은 머리글에 있음) |
| 2 | 게이트의 주황 훑기 호가 얼룩처럼 보임 | 하늘색 옅은 호로 |
| 3 | 1024×768: 오른쪽 단이 256px로 눌려 수치 칸이 깨짐(V1) | 960~1199px에서 두 단을 반반으로, 버튼 폭 축소 |
