# 포트폴리오 빌더 — 설계와 검증 기록

**날짜:** 2026-11-10
**요청:** "각 경험을 선택 가능하도록 모듈화하고, 특정 기업에 이력서나 포트폴리오 PDF로 제출할 때 원하는 경험만 골라 포트폴리오를 꾸릴 수 있게"
**사용법:** README의 "포트폴리오 빌더와 PDF"

---

## 1. 출발점

- 경험은 이미 모듈이었습니다. 원장의 경험 카드(`EXP-*.md`)가 하나씩 독립된 단위이고, `selection-guide.json`이
  직무군별 1순위·보조·제외 카드를 정해 두고 있었습니다. 없던 것은 "골라서 문서로 만드는 길"입니다.
- 기존 `public/portfolio.pdf`는 스크립트에 문장을 직접 적어 만든 것이라 원장과 갈라져 있었습니다
  (My Agent Switchboard 설명이 사이트와 달랐고, 수치·기간이 고정 문구였습니다).

## 2. 결정

| 결정 | 이유 |
|---|---|
| 모듈 = 공개 경험 카드 + 카드가 없는 프로젝트 사례 | 카드가 가리키는 사례(BEMS · MIS RPA 등)는 카드에 붙어 나갑니다. 따로 고르게 하면 같은 일이 두 번 실립니다 |
| 모듈마다 제외 · 요약 · 상세 | 선택 가이드의 1순위/보조와 맞물립니다(1순위 → 상세, 보조 → 요약). 전부 요약이면 이력서에 가깝고, 상세를 섞으면 포트폴리오가 됩니다 |
| 구성은 주소(URL)에만 저장 | 저장소는 공개입니다. 회사별 구성을 커밋하면 지원 대상이 드러납니다(`content/applications/`에 회사명을 두지 않는 것과 같은 이유) |
| 빌더는 공개 사이트의 `/builder/`, 메뉴에 없고 noindex | 서버가 없어 "나만 보는 페이지"를 만들 수 없습니다. 대신 이미 공개한 내용만 내려보내고, 고른 것은 어디에도 남기지 않습니다 |
| 비공개 카드(`publicOnSite: false`)는 실을 수 없음 | 위와 같은 이유. 프리셋이 그런 카드를 가리키면 빼고 알립니다 |
| PDF = 빌더 화면을 그대로 인쇄 | 브라우저에서는 인쇄(PDF로 저장), 명령에서는 같은 화면을 헤드리스로 인쇄. 문서를 그리는 코드가 한 벌이라 둘이 갈라지지 않습니다 |
| 문서의 문장을 빌더에서 고칠 수 없음 | 사실은 원장에서만 고친다는 원칙. 소개 문단을 회사마다 다르게 쓰고 싶으면 섹션을 끄고 자기소개서에서 다룹니다 |
| 제외 카드·확정 전 카드는 막지 않고 경고 | 무엇을 낼지는 사람이 정합니다. 다만 모르고 내는 일은 없게 합니다 |
| 추가 연락처는 기기(localStorage)에만 | 전화번호는 저장소에 두지 않는 정보입니다. 구성 링크에도 넣지 않습니다 |
| 문서 속 사이트 링크에 `?ref=코드` | 방문 통계에서 "이 PDF로 들어온 방문"이 구분됩니다. 바깥 링크(GitHub)에는 붙이지 않습니다 |
| 공개 기본 PDF의 구성은 홈 화면을 따름 | 새 선택을 만들지 않습니다: 주요 성과의 경험은 상세, 대표 프로젝트 중 카드 없는 사례는 요약 |
| 카드 본문의 `## 작성 메모` 절 | 아래 3번 |

## 3. 검증에서 찾은 것

정적 빌드를 Chromium으로 인쇄해 PDF를 쪽 단위 이미지로 확인했습니다(공개 기본 구성, 직무군 프리셋, 전부 요약).

| 발견 | 조치 |
|---|---|
| **카드 본문에 쓰는 사람용 메모가 섞여 있어 상세로 실으면 제출 문서에 그대로 나옴** ("자기소개서에는 ~을 씁니다", "(사용자 확정 2026-09-14)", "합산하거나 교환하지 않습니다" 등 10개 카드) | 카드에 `## 작성 메모` 절을 만들어 그 문단을 옮김(문장은 그대로). 이 절과 `## 확인이 필요한 것`은 PDF에서 뺌. 다시 섞이면 `lib/portfolio.test.ts`가 잡음 |
| `teamContext` 두 곳의 둘째 문장이 규칙("기여율을 추정하지 않는다", "단독 수행으로 기술하지 않는다") | 같은 카드의 작성 메모로 옮기고 `teamContext`에는 사실만 남김 |
| 인쇄에서 이름이 오른쪽으로 밀림 | 인쇄용 정렬 규칙이 머리 전체에 걸려 있었음 → 연락처에만 적용 |
| 재직기간이 두 줄로 접힘 | 이력표를 구분 · 기간 · 내용 세 칸으로 |
| 수치가 9개인 카드가 반 쪽을 차지 | 칸 대신 표의 줄(값 · 무엇 · 조건)로 |
| 그림이 쪽에 안 들어가면 글 사이에 큰 빈칸 | 그림을 본문 뒤로 |
| 제목만 쪽 끝에 남음 | 제목~한 일 목록을 한 덩어리로 넘김 |
| 요약 항목 하나가 통째로 다음 쪽으로 넘어가 반 쪽이 빔 | 수치 표는 줄 단위로 나뉘게 허용 |

결과: 공개 기본 구성 5쪽, '제조 AI·데이터' 프리셋 5쪽, 요약 8개 4쪽. 글자는 9pt 이상(테스트).

## 4. 남은 것 (사용자 확인 필요)

- BEMS 팀과제에서 본인이 맡은 범위. 지금 `teamContext`는 "사내 AI 전문가 과정의 팀과제다."뿐이라
  제출 문서의 "팀 작업 범위"가 범위를 말해 주지 못합니다.
- 소개 문단(`profile.summary`)은 모든 회사에 같은 글입니다. 직무군별 소개가 필요하면 원장에 직무군별
  문단을 두는 방식으로 넓힐 수 있습니다.
