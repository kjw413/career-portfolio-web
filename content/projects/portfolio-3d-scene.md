## 문제 정의

2026 하반기 지원서에 "입사 후 Three.js로 3D 원격 모니터링을 만들고 싶다"고 적었습니다.
포부는 확인할 방법이 없으면 문장으로만 남습니다.

## 제약 조건

- 채용담당자가 30초 안에 핵심을 읽는 사이트입니다. 3D가 읽기를 방해하면 안 됩니다
- GitHub Pages 정적 호스팅이라 서버가 없습니다
- 모바일과 저사양 기기에서도 페이지가 온전해야 합니다

## 설계

장식이 아니라 업무를 보여 주는 그림으로 만들었습니다. 사내 BEMS가 다루는 것, 즉 다섯
사업장의 전력·연료·용수 데이터와 실측·예측 구간(P05~P95)을 남한 지도 위에 도식화했습니다.
사업장은 실제 위치(시 단위)에 세우고, 데이터는 지도 서쪽에 띄운 화면 하나로 모입니다.

**켜지 않을 조건을 먼저 정했습니다.** 모션 축소 설정, WebGL2 미지원, 메모리 4GB 미만,
화면 너비 720px 미만, 청크 로드 실패 — 다섯 경우에는 같은 구도로 미리 렌더한 정적
이미지를 그대로 둡니다. 대체 경로를 먼저 만들고 장면을 나중에 붙였습니다.

## 구현

- React Three Fiber로 지오메트리를 코드에서 생성 (외부 3D 자산 없음). 해안선은 Natural
  Earth 공개 데이터를 단순화한 좌표 배열
- 데이터 펄스 30개를 InstancedMesh 하나로 처리, 공장 한 채는 지오메트리 하나
- 예측 구간은 정점 버퍼를 매 프레임 갱신하는 띠
- 색은 CSS 토큰에서, 공장 이름은 사실 원장에서 읽고 위치는 좌표표에서 찾음 (어긋나면 테스트 실패)
- 본문이 그려진 뒤 유휴 시간에 로드, 화면 밖에서는 렌더 정지

## 검증 결과

- 3D를 켠 상태와 끈 상태에서 첫 화면 렌더 시점 차이가 없도록, 장면을 별도 청크로 분리
- 360 · 768 · 1440px에서 가로 넘침 없음
- 모션 축소 설정에서 장면을 아예 불러오지 않음

## 본인의 역할

장면 설계, 구현, 대체 경로와 성능 조건 설정까지 전부 직접 했습니다.

## 배운 점과 다음 개선

기능을 넣는 것보다 넣지 않을 조건을 정하는 것이 어려웠습니다. 첫 판은 공장을 호 위에
늘어놓고 가운데 원반으로 모았는데, 뜻 없는 블록 높이가 뜻이 있어 보였고 알갱이가 어디로
가는지 읽히지 않아 지도 배치로 바꿨습니다. 다음에는 공장을 눌렀을 때 그 공장의 실적과
예측을 옆에 띄우는 것까지 해 보려고 합니다.
