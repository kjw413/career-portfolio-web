# 제출 이력 manifest

어떤 지원서에 어떤 경험 카드와 수치를 썼는지 기록합니다. 같은 사실을 회사마다 다르게
쓰는 일을 막고, 다음 지원서를 쓸 때 "지난번에는 이 문항에 어떤 카드를 썼는지" 확인하기
위한 것입니다.

## 회사명이 없는 이유

이 저장소는 공개입니다. 재직 중인 사람의 지원 대상 목록이 공개되면 현 직장에서 그대로
볼 수 있습니다. 그래서 **회사명과 직무명은 저장소에 넣지 않습니다.**

- 저장소에는 지원 시기, 직무군, 사용한 카드·수치, 검사 결과만 둡니다.
- 회사명은 구글드라이브의 파일명에 있고, `drive` 필드의 파일 ID로 찾습니다.
- 자기소개서 본문도 드라이브에만 둡니다. 여기에 붙여 넣지 않습니다.

`jobFamily`는 `content/ledger/selection-guide.json`의 직무군 이름과 같아야 합니다.
그래야 검사기가 "이 직무에 쓰면 안 되는 카드를 썼는지"를 확인할 수 있습니다.

## 항목 채우기

```jsonc
{
  "id": "2026H2-03",              // 시즌 + 일련번호. 회사를 유추할 수 없게
  "season": "2026 하반기",
  "jobFamily": "제조 AI·데이터",   // selection-guide.json 의 job
  "submittedAt": "2026-09-11",
  "outcome": "대기",              // 대기 | 서류 통과 | 불합격 | 미확인
  "drive": { "hwpx": "<fileId>", "txt": "<fileId>" },
  "analyzed": true,               // 본문을 읽고 카드를 확인했는가
  "questions": [
    { "no": 1, "topic": "가장 노력한 경험", "cardIds": ["EXP-..."], "metricIds": [] }
  ],
  "lint": { "ranAt": "2026-09-12", "status": "pass", "notes": [] }
}
```

`analyzed: false`는 파일이 있다는 것만 알고 본문을 아직 확인하지 않았다는 뜻입니다.
카드 목록이 비어 있어도 추측으로 채우지 않습니다.
