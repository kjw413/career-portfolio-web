# 사실 원장

지원서·자기소개서에 반복해 쓰이는 사실을 여기 한 번만 적습니다. 사이트 화면,
구글드라이브의 마스터 이력 문서, AI용 JSON은 전부 이 폴더에서 생성됩니다.

**여기가 아닌 곳에서 사실을 고치면 다시 갈라집니다.**

## 왜 이렇게 만들었나

2026년 9월, 같은 예측 오차가 사이트에는 `7%`, 마스터 이력에는 `7.3%`, 제출한
자기소개서 6건에는 서로 다른 5가지 값으로 적혀 있었습니다. 원인은 세 곳이 각자
갱신되고 서로를 참조하지 않은 것이었습니다.

그래서 수치를 문장에 직접 적지 않고 ID로 인용하게 했습니다. `metrics.json`의
한 줄을 고치면 사이트와 문서와 AI가 보는 값이 함께 바뀝니다.

## 파일

| 파일 | 담는 것 |
|---|---|
| `facts.json` | 학력 · 병역 · 경력 · 자격 · 어학 (공개 가능한 것만) |
| `metrics.json` | 모든 정량 수치의 값 · 단위 · 조건 · 근거 · 확정 상태 · 폐기된 표기 |
| `phrases.json` | 정본 표현, 사용 금지 표현, 지원일 기준 재계산 규칙 |
| `affiliations.json` | 타임라인 단위 소속 (회사 · 교육과정 · 학교 · 군) |
| `education.json` | `EDU-*` 교육 과정 기록 |
| `selection-guide.json` | 직무군별 1순위 · 보조 · 기본 제외 카드 |
| `open-questions.json` | 아직 확인되지 않은 항목과 그 처리 규칙 |
| `experiences/EXP-*.md` | 경험 카드 — 카드 하나 = 경험 하나 |

## 상태 표기

| 상태 | 뜻 | 사이트 | 지원서 |
|---|---|---|---|
| `확정` | 사용자 확인 또는 공식 증빙 | 노출 | 사용 |
| `진행중` | 아직 끝나지 않은 일. 종료일 없이 기준일 표기 | 노출 | 사용 |
| `부분확정` | 핵심은 확인됐으나 일부 날짜·수치 근거가 부족 | 확정된 부분만 | 조건 확인 후 |
| `미확정` | 지원서 입력 전 사용자 확인 필요 | 노출하지 않음 | 사용하지 않고 질문 |

## 수치 쓰는 법

본문에 숫자를 직접 적지 않고 인용합니다.

```markdown
전 공장·전 에너지원 평균 {{metric:forecast-mape-all}}를 달성했습니다.
```

`{{metric:id}}`는 `display`를, `{{metric:id|label}}`처럼 쓰면 다른 필드를 채웁니다.
카드 본문에서 인용한 수치는 그 카드의 `metricIds`에도 있어야 하고, 없으면 빌드가
실패합니다.

새 수치를 등록할 때 반드시 채우는 것:

```jsonc
"my-metric": {
  "display": "월 4시간",          // 화면과 문서에 나가는 표기
  "label": "무엇을 잰 값인가",
  "condition": "어떤 범위·기간의 값인가",
  "basis": "무엇을 근거로 아는가",   // "사용자 확정 2026-09-12" 처럼
  "status": "확정",
  "cardIds": ["EXP-..."],
  "deprecated": ["월 15시간"]      // 옛 표기. 다시 쓰이면 검사기가 잡습니다
}
```

## 카드 쓰는 법

`experiences/_TEMPLATE.md`를 복사합니다. 파일명이 곧 `id`입니다.

- `headline` — 타임라인에 보이는 한 줄 결과
- `highlights` — 훑어볼 구체적 사실 1~4개 (공개 카드는 필수)
- `canonical` — AI가 그대로 써도 되는 정본 문장
- `forbidden` — 쓰면 안 되는 표현. 사이트에는 렌더링하지 않습니다
- `useFor` / `excludeFor` — `selection-guide.json`의 직무군 이름과 같아야 합니다
- `publicOnSite` — 확정 전에는 `false`. `미확정` 카드는 `true`로 둘 수 없습니다

본문에는 `## 수행`이 반드시 있어야 하고, `확정` 카드에는 `## 성과`도 필요합니다.

## 무엇이 빌드를 멈추나

`npm run lint:ledger`가 아래를 검사합니다.

- 존재하지 않는 수치 · 카드 · 프로젝트 · 확인 항목 · 직무군을 가리키는 참조
- 본문에서 인용했는데 `metricIds`에 없는 수치
- 공개 카드가 인용한 `미확정` 수치, `미확정` 카드의 사이트 노출
- `YYYY-MM`·`YYYY-MM-DD`가 아닌 날짜, 시작일이 종료일보다 늦은 기간
- 소속이 자기 카드를 빠뜨린 경우, 같은 직무에서 쓰면서 동시에 제외하는 카드
- 원장에 섞여 들어온 전화번호 · 주민번호 · 상세주소 패턴
- 사이트 콘텐츠에 다시 나타난 폐기 수치와 금지 표현

## 고치는 순서

```
사용자가 사실을 확정
  → content/ledger/ 수정 (basis · confirmedAt 기록, 옛 표기는 deprecated로)
  → npm run lint:ledger && npm test
  → 커밋 → 배포
  → 사이트 · public/ai/ledger.json · 드라이브 미러가 함께 갱신
```

확정되지 않았으면 원장을 고치지 말고 `open-questions.json`에 질문을 추가합니다.
